# 世界美术与状态反馈 v0.9

审查输入为实际 Play 相机截图 `outputs/v08-world.png`。画面中棕土地层、紫色页岩、亮薄荷打印舱和暗青机器分别占据不同色彩体系；人物与背景明度过近，打印舱反而成为最亮、最饱和的大块。上一轮仅降低工业材质饱和度，未解决这些关系。

## 统一规则和具体落点

世界色彩规则集中在 `DeepArtPalette.cs`。用暖灰矿物地层承托低饱和青绿工业物，人物保留暖白头盔和肤色。活跃状态用青绿，短时确认用暖黄，异常用铜橙。角色和可操作设备应比洞壁清楚，打印舱仍是地标但不淹没邻近人物。

| 对象 | 原画面问题 | 实际修改 |
|---|---|---|
| 土壤 | 偏棕、单独一套色温 | 调色基准 `#6E6555`，保留原纹理的局部明暗 |
| 砂岩 | 与土壤明度相近 | 较浅的 `#857A62`，保留横向沉积纹理 |
| 页岩 | 明显偏紫 | 青灰 `#4D5C5C`，保留片岩裂纹 |
| 玄武岩 | 蓝色过强 | 更深的蓝灰 `#3C4E53`，仍与其他岩层区分 |
| 设备 | 青黑、细节被暗光吃掉 | 工业材质饱和度 0.82、AO 0.28、最低填光 0.12；中性全局光强 0.56 |
| 人物 | 与背景明度重合 | 独立 `WorkerLit.mat`，AO 0.20、最低填光 0.38，略暖的白色响应；雾气仍负责可见范围 |
| 打印舱 | 薄荷绿照明和玻璃过亮 | 中性暖白局部光 0.30、玻璃 alpha 0.16、扫描线 alpha 乘 0.35；不再整个等待阶段伪装成生产 |
| 洞壁和后处理 | 偏蓝、重对比进一步压暗物体 | 洞壁统一蓝灰；对比 3、曝光 0.10、饱和 -3、Bloom 0.10、暗角 0.12 |

地形使用同一张原始 Color 的“源材质颜色 → 目标颜色”比例映射，再沿原有不规则边界混色。Color PNG、Alpha、Normal、AO、Sprite UV、图集切片和碰撞格均不变；不是对截图修色。AO 与法线仍由各素材原来的 Secondary Texture 提供。地形的调色不应用到角色、工具和工业设备。

## 动态只说明真实状态

- 手工作业和研究的扫描/风扇仍只在真实 Working 订单中运行；阻塞、缺料或停机时不假装工作。
- 打印舱扫描表示“有可领取的人员候选”，不再在冷却计时期间持续做生产动画。
- 开关操作直接触发 0.34 秒的局部状态灯确认，实际时间驱动，因此暂停时点击仍有反馈。响应只改变小仪表的颜色和比例，连续点击不会累计放大，之后回到原始比例。
- 仓储使用 `DeepInventory.ReceivedUnits / DispatchedUnits` 的真实成交计数；物料预留和取消不造成假进出。等量输入与输出、总占用不变时仍可产生短暂反馈。入库为青绿、出库为暖黄，0.5 秒后归于待机。当前库存本来就是共享仓储，因此这里反馈共享仓储的真实变化，并未虚构每个箱子的独立物流库存。
- 制氧气泡继续读取逐设备实际气体交换量；底座、受力点和气路端口保持固定。

## GitHub 指南与对应实现

读过的原始指南：

1. [nitzangames/procedural-game-art — SKILL.md](https://github.com/nitzangames/procedural-game-art/blob/main/SKILL.md)。采用共享色彩/动态规则和同一场景反复渲染的做法：实际落点是 `DeepArtPalette`、源/目标地形调色场、统一灯光升级，以及再次渲染真实 Play 场景。只借鉴其视觉组织方法；项目继续使用已有 Blender 资产。
2. [gamedev-skills/awesome-gamedev-agent-skills — game-feel/SKILL.md](https://github.com/gamedev-skills/awesome-gamedev-agent-skills/blob/main/skills/disciplines/game-feel/SKILL.md)。采用“由离散事件触发、短暂增强后回到静止、效果不扰动模拟”的原则：实际落点是开关确认、真实仓储成交计数和状态灯缓出。殖民经营的普通开关不加入镜头震动、停帧或输入阻塞。

本轮将这些指南作为设计参考，没有执行仓库中的安装脚本，也没有引入第三方运行时、远程服务或不兼容的引擎示例。

## 验证入口

运行 `DeepPresentationUpgrade.ApplyToCatalogAndLoadedScenes(catalog)` 应用材质、预制体与已载场景灯光。运行原有 `ValidateCatalogGrounding` 检查底脚和贴图配准，再运行 `ValidateMachinePresentation`；后者新增预留无仓储反馈、等量进出仍有反馈、暂停下开关确认、连续点击不会累计缩放的回归检查。最后重新渲染同一实际场景检查地层辨识、人物可读性和打印舱亮度；实际执行结果在本轮总验收报告中记录。

## 已有场景的 Play 兼容

`DeepWorldArtUpgrade` 在每次进入 Play 和随后加载场景时自动接入本项目 `DeepPressureWorld`，因此新保存的 `DeepPressureColony 15` 等场景也会应用本轮世界配色，无需重新生成地图。对建筑和人物使用 MaterialPropertyBlock，保留原共享材质与贴图；对名为 Ambient 的全局光及建筑内 Printing chamber light / Work light 做一次角色校准。其他自定义灯不改，运行中随后手动调参不被反复覆盖。新打印人物和新建建筑在 0.35 秒内接入同一规则。

旧场景仓库的已知 `Stacked bin` 子物体会在 Play 中禁用，并按原始 crate PNG 实测不透明范围重新对齐剩余单箱；仅改变 Visual 子物体，不改变建筑坐标。缺少动态部件的旧手工作台会得到小型状态面板与屏幕扫描，使用一个由该 world 持有并在销毁时释放的白色几何 Sprite，不创建或泄露材质实例。此兼容层只在 Play 中运行，不写回场景资产或存档。

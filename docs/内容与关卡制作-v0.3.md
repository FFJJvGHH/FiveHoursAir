# 内容与关卡制作 v0.3

本轮把经营内容拆成独立 ScriptableObject：物品、建筑、科技和配方由配置资产决定；关卡保存这些资产的实例。玩家界面显示名称、数量、前置与实际状态，不展示工程路径或内部实现编号。

## 作者入口

使用 Unity 顶部菜单 **深压 → 内容编辑器**。工作台有物品、建筑、科技、配方四个列表，可搜索显示名与稳定 ID。右侧显示占格、成本、科技前置、供电/用电、仓容和端口示意，并直接编辑对应资产。

第一次可点击“补齐基础内容”；它调用 `DeepCatalogBuilder.CreateOrUpdateCatalog()`，在 `Assets/DeepPressure/Data/Gameplay` 创建缺失的资产和建筑 Prefab。已经存在的配置数值与 Prefab 保留，生成地图不会重新写死成本或覆盖人工调整。“创建独立条目”建立新资产并把它加入当前目录。图标和模型可以替换，规则仍保留在定义资产。

该入口是编辑器制作工具。Play 期间不创建目录、修改定义或摆放关卡实例。脚本导入不自动打开窗口、不切换用户正在查看的场景。

## 数据关系

| 资产 | 关键内容 | 引用方式 |
|---|---|---|
| `DeepItemDefinition` | 稳定 ID、显示名称、描述、图标、颜色 | 成本和产物直接引用资产 |
| `DeepBuildingDefinition` | Prefab、占格、工时、角色、成本、科技、通行、支撑、电力、燃料、仓容、端口 | 关卡实例引用定义 |
| `DeepTechDefinition` | 工时、研究消耗、前置科技 ID | 运行时研究状态另存于会话 |
| `DeepRecipeDefinition` | 输入/输出、工时、所需工作台 ID、科技条件 | 制造订单引用配方 |
| `DeepGameplayCatalog` | 以上四类资产的清单与查询 | 游戏会话引用一个目录 |

`DeepItemAmount` 保存物品资产和整数数量；没有第二套隐藏物品序号。建筑 `requiredTechId` 是解锁条件的唯一依据。科技 `unlockBuildingIds` 是初始内容的可选说明摘要；工作台的“实际解锁”直接查询建筑条件，不根据摘要决定能否建造。

ID 用于科技、配方和存档关联。建议用字母、数字、下划线或短横线；名称可自由使用中文。已有内容的 ID 不应为了改显示文字而重命名。修改 ID 后运行“检查目录”，同步调整引用它的前置和工作台字段。

## 已配置的起步内容

物品：`ore` 矿石、`alloy` 合金、`electronics` 电子元件、`research_data` 研究数据。初始库存由关卡的会话设置决定，目录不会凭空给每个场景发资源。

| 建筑 ID | 显示名 | 占格 | 主要作用 |
|---|---|---:|---|
| lamp | 工作灯 | 1×1 | 耗电 1；可墙挂、不要求地板 |
| ladder | 梯子 | 1×1 | 连续梯段提供垂直通路 |
| floor | 地板 | 1×1 | 阻挡该格并给上方提供支撑 |
| storage | 仓库 | 3×2 | 提供 200 单位共享库存容量 |
| generator | 地热供电机 | 3×3 | 向旧站地热母线取电，供给 20；本样机不消耗燃料 |
| research_bench | 研究台 | 2×2 | 耗电 5；工作人员执行研究 |
| fabricator | 合成台 | 3×2 | 耗电 4；工作人员执行配方 |
| gas_tank | 气体储罐 | 2×3 | 有限气体容积和独立端口 |
| gas_regulator | 调压机 | 2×2 | 耗电 2；限制下游压力 |
| gas_separator | 分离塔 | 3×4 | 耗电 6；产品/尾气双出口 |

设备可以从前方走过，但仍占用建造空间，禁止互相重叠。`blocksMovement` 与 `footprint` 不应合并成一个属性。只有地板/实体结构阻挡通行；普通工作台、仓库、发电机和气体设备默认不挡路。人物的路径、订单和工时由运行时系统负责，不能因场景里有一个人物 Sprite 就当作调度已完成。

### 三层科技

`survey_basics` 地下测量 → `pressure_engineering` 压力工程 → `selective_separation` 选择分离。分别解锁储罐、调压机和分离塔。研究台与基础合成台无需前置科技，从而可以先生产研究数据，再启动第一层研究。

### 合成链

| 配方 ID | 输入 | 输出 | 工时 | 工作台 |
|---|---|---|---:|---|
| smelt_alloy | 矿石 ×3 | 合金 ×1 | 8 秒 | 合成台 |
| assemble_electronics | 合金 ×2 | 电子元件 ×1 | 12 秒 | 合成台 |
| compile_research | 电子元件 ×1 | 研究数据 ×2 | 10 秒 | 合成台 |

这些是架空加工配方，不声称代表现实工艺。输入是有限库存；输出占用仓容。库存容量、物料预约、取消返还、工人能否到达和工作台电力属于运行时验收，目录只定义相应规则与数值。

## 建筑 Prefab 制作规范

Prefab 根位于占格矩形的左下角；`DeepBuildingInstance.origin` 记录左下格坐标。图片可以有透明边，但占格不从图片尺寸反推。`Visual` 子对象承载 Sprite 与灯光，设备图可更换为其他分辨率而不移动逻辑格。

初始 Prefab 复用现有 Blender 的罐、压缩机、分离塔，以及独立箱子、控制台、通风格栅等素材。梯子、地板和灯具用独立小部件组装。带多贴图的 sprite 继续使用 `_NormalMap` 与 `_AOMap`，不把整个建筑或场景烘进背景。

灯具 Prefab 绑定 `Light2D[] lights` 和发光 sprite；其开关和电力状态由实例控制。工业 Prefab 还包含 `GasNode` 与 `DeepDevicePlacement`；管线仍由 `GasLink` 显式连接。端口在定义中给出局部坐标，图像碰到另一张图不构成连通。

人工修改 Prefab 后，“补齐基础内容”不会重建它。新增建筑可以指定自己的 Prefab，也可以先点击“创建缺失 Prefab”得到基础结构，再在 Prefab 模式调整。不要把修改运行中实例当成保存了定义或 Prefab。

## 可重复的关卡制作流程

1. **定义规则。** 在内容编辑器填写物品、建筑、配方和科技。先把一条资源链的输入、产物、工时与成本配置完整。
2. **检查目录。** 检查重复/空 ID、缺失 Prefab、无效物品引用、缺失科技、科技循环、错误工作台与端口越界。修正后再进关卡。
3. **制作地形。** 在辅助“关卡工作台”画真实 Tilemap，按波状层面、透镜体和裂隙布置材料。保存地图，不依赖 Play 时生成。
4. **定义区域。** 区域标签用于任务和勘探；墙、门和地形的连通决定物理房间。两者分开检查。
5. **放置基础设施。** 把建筑列表项拖入 Scene，或选“在 Scene 点击放置”。工具吸附格网，预览占格；禁止越界、地形重叠、建筑重叠，并检查要求地板的设备是否有支撑。Esc 结束放置。
6. **放置人员与库存。** 在游戏会话上指定目录、起始库存和工人；给工人可站立的起点及连续梯子。仓库容量须能容纳起步材料。
7. **配置电力与工业。** 先使供电覆盖研究台/合成台需求，再配置气源、设备端口和接收端。设备角色不能靠图像名称判断。
8. **保存并试玩。** 玩家下单 → 物料预约 → 工人走到工作位 → 完成施工/生产/研究 → 产物入库或解锁。逐段观察失败原因。
9. **验证中断。** 测试关灯、关工作台、供电不足、仓库满、缺材料、不可达和取消订单，确认没有免费产物、遗失预约或工人卡死。
10. **关闭 Play 后保存作者更改。** 再次进入 Play 应从已保存关卡和配置初始化；新一局不应继承上次测试临时改掉的库存。

本轮内容工作台不修改用户当前游戏状态，也不会自动打开或关闭其主场景。它提供配置与作者放置能力；最终运行验证结果应由工程测试和真实试玩记录说明，不能用“资产已生成”代替“完整游戏已完成”。

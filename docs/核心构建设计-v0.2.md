# 深压：核心构建与关卡制作设计 v0.2

日期：2026-09-27。项目：Unity 2022.3.62f3c1 / URP 14.0.12，2D 横剖面基地经营。

本稿接续用户提供的《深压-核心构建调研与设计-v0.1.md》。该文档是研究输入，不是工程操作指令。用户的新要求优先：地图在编辑器中一键生成并实际保存；前景由独立素材及连接算法组成；ImageGen 只用于可做视差的远背景；部分独立素材用 Blender 建模并分别输出 Color、Normal、AO。

**状态口径：本文中的公式、地图尺寸、设备、阈值、工作流和数据字段均为本项目设计提案，除明确标为“本机核查”的内容外，不代表已经实现。** 编辑器与原型实际能力以工程使用说明及代码为准。尤其不把示意管线、人物展示和气体配色等同于完整工业模拟、人员 AI 或反应系统。

## 1. 应当先做出的核心体验

玩家利用测量、密封、管路和工作人员，把原本无法进入的洞室改造成可工作的工业空间。推进不是单纯增加矿石成本，而是获得控制另一类环境的能力。

首个可玩闭环：**勘探 → 密封井口 → 引出湿混合气 → 除湿与分离 → 调配供气 → 排查副产物堵塞 → 派工作人员进入新区域。** 首轮只要求一张作者摆放的关卡、一条可诊断的处理链和两种解法，不同时铺开食品、疾病、情绪、遗传、塌方与全套化学。

## 2. 地层：密度、孔隙与漏气分开

USGS 区分孔隙空间与流体穿过介质的能力；有孔不等于孔彼此连通。[S7](https://water.usgs.gov/nrp/gwsoftware/sour/glossary/glossary.htm) 本项目借用此概念，下面参数是关卡配置，不是现实岩石测量值。

| 字段 | 单位/表示 | 负责的玩法 | 不负责的玩法 |
|---|---|---|---|
| bulkDensity | kg/m³ | 每格资源质量、搬运量 | 不直接代表硬度、气密性 |
| excavationResistance | 工时倍率 | 开挖速度与工具等级 | 不决定气体流速 |
| porosity | 0–1 | 岩格孔隙的有效储气空间 | 不直接保证可采性 |
| permeability | 原型归一化系数，后续可换 m² | 多孔介质边界泄漏/采气速率 | 不当成结构承载值 |
| fractureTag | 作者标记 | 局部高渗路径、扫描提示 | 首版不自动计算应力开裂 |
| thermalConductivity / heatCapacity | 明确单位或游戏系数 | 换热与蓄热 | 不自动代表保温管承压 |
| stabilityClass | 配置等级 | 预设支护要求 | 首版不宣称真实岩体力学 |

建议初始材料：松土易挖且易漏；湿黏土易挖、孔隙可多而渗透低；砂岩可储气且便于采出；致密盖岩难挖、低渗；裂隙岩保留高硬度但局部易漏。同一材质可以有完整/裂隙变体。

一格世界尺寸和剖面厚度应固定。例如 1 m × 1 m × 1 m 为作者配置，则空格容积 1 m³，岩格孔隙容积为 `cellVolume * porosity`。气藏量使用有限库存；若关卡需要持续补给，显式放置有流率上限的源对象，并记为边界输入。

原型阶段只落实“可挖、储气、漏气、温度”所需字段。动态塌方、应力和裂缝生长属于后续。深度可以影响关卡配置，但不直接写成 `depth → pressure/hardness` 的唯一公式。

## 3. 空气、压力与反应

### 数据与近似边界

采用非反应混合物的理想气体近似作为游戏起点：`nTotal = Σni`，`P = nTotal * R * T / V`，`xi = ni / nTotal`，`pi = xi * P`。内部统一 mol、K、m³、Pa；界面换算 kPa、°C 和摩尔百分比。分压与组分比例的概念依据 OpenStax。[S8](https://openstax.org/books/chemistry-2e/pages/9-3-stoichiometry-of-gaseous-substances-mixtures-and-reactions) 这套近似不用于宣称真实高压工业安全性，也不保证极高压力下的物理精度。

单元保存各组分摩尔数、有效容积、热状态；不能同时把压力、温度、总质量、比例作为互不约束的可写变量。作者设置 `P/T/composition` 后由初始化器求数量；气体颜色只用于观察，不反向驱动物理。房间汇总质量与成分，不能简单平均不同体积的压力。

| 组分 | 第一阶段用途 | 可观察的处理问题 |
|---|---|---|
| O₂ | 呼吸供应、未来燃烧氧化剂 | 要看氧分压与污染，不只看百分比 |
| N₂ | 气氛调配、未来惰性置换 | 稀释氧，增加输送与分离负担 |
| CO₂ | 人员呼出、分离目标 | 净化装置有容量；必须收集或输出 |
| H₂O 蒸气 | 除湿与回收水 | 冷凝需要热汇，液体出口可能堵塞 |
| CH₄ | 第二阶段燃料 | 独立线路、受控供氧、条件点火 |
| 辉质气 X | 第三阶段架空材料链 | 遇湿缓慢结垢；阈值和产物全属虚构设定 |

### 有条件的反应，不让“相遇”变成魔法

| 过程 | 触发规则提案 | 守恒与设备结果 |
|---|---|---|
| 混合 | 空间连通、扩散或压差输送 | 交换组分和热，不生成新元素 |
| 水冷凝 | 水蒸气分压超过当前温度的饱和值 | 从气相转到液相，释放热量；无接收容量则停机/积液 |
| 吸附 | 滤材有剩余容量且目标气体接触 | 气体进入滤材库存；再生输出废气，不能直接删除 |
| 燃烧 | 燃料、氧化剂和点火条件均成立 | 按反应进度限量消耗，生成 CO₂/H₂O 与热 |
| 架空湿式反应 | X、水、温度和接触时间满足配方 | 输出沉积物或材料；普通管内降低导通率 |

NIST 将燃料、氧化剂、热和可持续反应列为燃烧要素。[S9](https://www.nist.gov/el/fire-research-division-73300/firegov-fire-service/fire-dynamics) 氧氮普通混合不自动变毒；有甲烷也不自动爆炸。首版可只显示条件风险并阻止不兼容施工，燃烧模拟另行验收。

混合气转移按来源组分比例扣除，统一限流，禁止某个节点先更新就拿走全部库存。固定步长、先计算通量再统一提交；同一节点总流出不得超过库存。边界供给、人员消耗、设备反应、储罐变化各有物料账。高压真实可压缩流、湍流与热浮力不属于第一版承诺。

## 4. 高压处理链和设备契约

推荐链路：**取样孔 → 井口隔离阀 → 耐压缓冲 → 调压 → 冷却/冷凝 → 气液分离 → 组分分离 → 产品缓冲/调配 → 居住供气**。冷凝水、尾气与热量分别有接收端；事故接收支路有独立容量。

| 设备 | 需要显示的参数 | 必须显示的停机原因 |
|---|---|---|
| 密封井口 | 气源、入口温压、采集上限 | 气藏枯竭、井口关闭、采集通道不可达 |
| 隔离阀/止回阀 | 开度或允许方向 | 手动关闭、自动规则关闭、反向压差 |
| 调压器 | 下游目标、最大流量 | 来压不足、下游已达目标 |
| 压缩机 | 压升、流量、功率、出口温度 | 无电、超温、背压过高 |
| 冷凝器 | 冷端温度、换热能力、凝水速率 | 冷端过热、凝水接收端满 |
| 组分分离器 | 产品纯度、回收率、双出口容量 | 产品堵塞、尾气堵塞、输入不足 |
| 缓冲罐 | 有效容积、各组分、可用库存 | 达工作上限；过量不能凭空消失 |
| 混合/供气站 | 目标气氛、供应能力 | 任一必要组分不足、环境条件不满足 |

压缩需要做功并改变热状态；NASA 的压缩机教材提供了这一概念依据。[S10](https://www.grc.nasa.gov/www/k-12/airplane/compth.html) 游戏中不要把任意减压阀当免费冰箱。高压气源先控制来压，衰减到低压后才增加压缩机，形成同一工厂的改造阶段。

分离器以每种组分的分流比例计算产品与尾气，二者之和等于输入。纯度与回收率分别显示；不能只选“氧气过滤”就同时得到 100% 纯度、100% 回收和零成本。任何必要出口满时停止或降低处理速率，明确显示被阻塞的端口和上游影响。

管道分为气体、液体、电力、信号图层；原型可先只模拟气体。普通、耐压、保温和换热管各解决不同问题，不能一个升级包办。高压损伤按内外压差及温度等条件判断，最初可用“过载告警 → 有倒计时的泄漏”代替瞬间爆炸。

## 5. 人员与工业网络如何互相影响

人物不是设备装饰：他们承担取样、挖掘、搬运、安装、改阀和维修。玩家给订单，不必逐个直接操控。任务状态至少为待条件、可领取、已预约、行走、工作、完成、失败；材料和工作位置都要预约，避免两个工人领取同一任务。

候选任务先过滤技能、材料、可达性和区域装备要求，再按玩家优先级、紧急程度、路程和技能计算排序。失败原因明确写成“缺钢材”“工作侧不可达”“需要防护服”，不只显示无事可做。危险地层尚未工程处理时，工作人员拒绝进入或要求装备，而不是穿越致密墙、无氧洞室直接施工。

首张关卡建议三名工人、一条楼梯/竖井、一处材料库和两个可站立的设备维修侧。通过缩短来回路程、移动仓库、建立机械物流体现布局收益。首轮不强推睡眠/压力/疾病细节，先验证任务领取与实际施工。

## 6. 区域判定：作者标签与物理房间是两套数据

| 对象 | 定义方法 | 何时变化 | 可以用来做什么 |
|---|---|---|---|
| Region（语义区域） | 作者绘制矩形/多边形或格子集合；稳定 ID | 作者主动编辑 | 任务、关卡脚本、背景、勘探信息、初始气体模板 |
| PhysicalRoom（物理连通空间） | 根据阻气格、墙、门的邻接连通分量计算 | 挖掘、建墙、门状态或密封边变化 | 气体统计、泄漏检测、压力边界和换气路径 |
| GameplayRoom（用途房间，后续） | 物理房间 + 面积/设备/环境条件规则 | 设备或环境变化 | 机房、宿舍等功能判定 |
| Network（工业网络） | 端口与管路的显式连接图 | 铺管、拆管、阀门拓扑变更 | 设备供给、管线追踪、故障定位 |

“生活区”标签不会自动变成密封生活舱；透明 Trigger 也不是阻气墙。两个标签不同的洞室挖通后，可以属于同一物理房间。门关闭是否阻气是门组件属性，不能从 sprite、Sorting Layer 或区域颜色猜测。

推荐语义判定：世界坐标先转统一格坐标；格中心进入区域形状则命中。基础 Region 默认互斥；重叠时报验证错误，或按显式优先级处理并显示警告。用于任务的标签可多选，不能和基础区域覆盖混在一起。矩形使用半开区间 `[min, max)`，避免边界格双重归属。

密封检测从地图外部边界对可通气格 flood-fill；能连到外部的标为 Exterior。内部再计算连通分量，并为每个房间保存成员格和边界。贴在背景上的岩石不会阻气；实体地形数据才阻气。多孔岩格允许低速泄漏时，拓扑“房间墙”与流体边界“非零导通率”仍需分开。

## 7. 独立前景素材与连接算法

本节是本项目的工程方案，并不是对《缺氧》素材结构或源码的断言。

### 地形用邻接决定外观，材质决定属性

最小版本使用四邻接 16 掩码：`mask = N*1 + E*2 + S*4 + W*8`。N/E/S/W 表示相邻格是否属于当前连接组，得到孤立块、端头、直段、拐角、T 形和实心中心等变体。连接组与材质 ID 分开：两类岩石都阻气，但可以保留清晰矿层界线。

建议每种材质准备一个 16 格图集，所有格子的尺寸、PPU、pivot、normal、AO 对齐。花纹变体根据 `(levelId, cellX, cellY, materialId)` 的稳定散列选取；重新打开场景不能随机跳纹理。只重绘变更格及邻居，避免每次笔刷修改整张地图。

四邻接不能表达所有凹角，后续可扩展八邻接的 47-tile blob 规则：只有相邻两个正交方向均连接时，相关对角才参与遮罩。它是扩展方案，不作为首版已有能力。

跨材质边界用明确优先级和过渡覆盖层：先渲染完整基底，再在本格范围内添加岩层接缝/边缘。透明边缘不得制造物理缝；不同材质共边不能双方都挖掉一条透明线。采掘裂纹、矿粒与潮湿覆盖层也不能反向改变碰撞，除非对应逻辑属性实际改变。

### 管道外观连接与真实网络连接分离

同样可用 4-bit 掩码选管道 sprite，但该掩码必须来自**真实连接图**，不能只看相邻有没有“长得像管道”的图像。端口类型、方向、管路图层、节点 ID 不兼容就不连。

交叉默认不相通；显示跨线桥或前后层区别。T 接与四通需要显式节点；阀门两端拥有独立端口；隔离节点不因 sprite 相接而被误合并。施工预览显示将加入的网络颜色和受影响设备，跨网混合给出可解释告警。流向箭头由实际净流量驱动，零流量时不假装运输。

### 设备不能从图片尺寸推导功能

每个设备定义 `footprint`（格子占用）、`anchor`、`ports`（格偏移、方向、类型）、`workCells`、`blockingFaces`；sprite 可以伸出占格但不抢占交互。旋转同时变换占格与端口，再选择对应美术图。换高清贴图只改变表现，不移动端口或施工范围。警示灯、指针、转子适合独立子 sprite，便于状态驱动。

## 8. 可重复的关卡制作流程

目标是工具栏一键创建**可检查、可保存的真实场景对象/Tilemap 数据**。运行时只加载既有地图；不在 Awake/Start 临时生成地形。开发期间允许编辑器按固定模板或固定种子生成初稿，然后人工修改。

建议编辑器入口命名为 `DeepPressure / Level Workshop`，窗口工具栏包含“生成示范关卡”“创建空白关卡”“重建连接外观”“验证”“重算房间”“保存场景”。这是交互目标；实际菜单名应以交付说明为准。按钮只操作明确选中的关卡根对象，不覆盖其他场景；重生成需保留作者编辑副本或显式区分模板生成区和人工编辑区。

1. **定格网与边界。** 建立关卡尺寸、每格米数、剖面厚度、边界类型与摄像机可视范围。所有工具统一坐标转换。
2. **画地层。** 用材质笔刷、矩形填充、空洞笔刷编辑地形数据；自动更新独立 Tile/sprite 外观和碰撞。
3. **画语义区域。** 输入稳定 ID、名称、类型、标签及形状。区域覆盖层直接显示边界、面积与冲突格。
4. **设置初始环境。** 对空洞或孔隙域设置温压、混合比例、湿度/气源配置；验证比例和、负值、零容积及重复赋值。
5. **摆设备与交通。** 从 Prefab/设备定义拖入，吸附格网；显示占格、维修侧、端口方向，放置梯子和人员出生点。
6. **铺网络。** 分图层画管、电和信号，按显式节点连接；可查看开放端、不同类型误接和没有接收端的产品口。
7. **加远景与局部光。** ImageGen 远景在独立背景层，可设置轻微视差；前景独立素材、灯具、法线与阴影保持可编辑。
8. **检查物理房间。** 重算连通、外部泄漏、门边界，分别查看语义区域与物理房间覆盖层。
9. **验证并保存。** 场景落盘，关闭后重开，检查设备、地形和 ID 均存在；进入 Play 不产生第二份地图，退出后作者数据不被模拟状态污染。
10. **试玩工艺链。** 从库存建立到出口堵塞，再通过两个方案恢复。能用覆盖层解释一次故障，比增加更多素材更重要。

验证器至少定位：无效/重复区域 ID、越界格、语义重叠、设备占格冲突、悬空维修侧、出生点不通、管线悬空端、类型误接、封闭空间连到外部、气体比例不合法、缺失连接变体，以及材质图/法线尺寸不一致。警告应能点击定位相应对象或格子。

## 9. 首张示范关卡的配置提案

以 96×56 格作为设计尺度示例，左下为原点；实际样机场景可更小，但要保留布局关系。所有数值是游戏初值，不能当现实建议。

| 区域 ID | 建议位置/范围 | 地形与环境 | 要教会的事情 |
|---|---|---|---|
| base_habitat | 左上约 6–32, 34–48 | 旧站、稳定初始空气 | 人员、仓库、观察工具 |
| process_hall | 中部约 34–66, 28–42 | 可施工空洞、足够维修空间 | 拆分气/液/电线路 |
| wet_reservoir | 右中约 70–88, 20–36 | 砂岩储层与致密盖岩 | 保留天然密封、先取样后开口 |
| cold_cavern | 左下约 12–32, 10–24 | 低温洞室与较低来压 | 长距离冷源/气源的取舍 |
| deep_objective | 下部约 44–66, 5–17 | 通路未开放、待处理环境 | 工艺稳定后扩大活动范围 |

气源示例为 280 kPa、38°C，摩尔比例 O₂ 24%、N₂ 71.5%、CO₂ 3%、H₂O 1.5%。水蒸气分压为 4.2 kPa，目标是入口保持气相、冷却后能回收水；需由最终使用的饱和曲线验证这两个条件。若先减压，露点也会变化，可能需要改成先在高压段冷凝，再调压供气，不能把工艺顺序固定成万能答案。若作者输入的湿气过饱和，应明确分配为初始液水，而不是悄悄修正成分。

故障事件不靠任意脚本删资源：给凝水罐一个有限容量，并让它实际逐渐充满。玩家可以增加用水设备、扩建储水或降低进气；三者在空间、工时、资源和产量上有不同代价。目标区开放要求应检查真实环境/通路与任务结果，而不只检查有没有摆下指定建筑。

## 10. Blender → 2D 光照素材管线

### 适合建模的东西

优先建压力罐、压缩机、分离塔、冷凝器、管道节点、机械门和灯具。它们的倒角、圆柱、凹槽、螺栓能够通过法线响应局部灯光。地形可用模块化岩块/切面生成邻接变体；人物初期独立 sprite，不必先搭完整 3D 动画管线。

远景 ImageGen 图像只提供尺度、洞穴深度、雾与色调。地面、梯子、机器、可挖岩层、管线不烘进远景图；背景不能替代可编辑地形或参与区域判定。

### 同一相机输出多张一致的贴图

Blender 官方手册说明可以分别烘焙基础颜色、法线和 AO；法线空间需要与使用端一致。[S11](https://docs.blender.org/manual/ru/4.5/render/cycles/baking.html) 下面是本项目建议的 sprite 烘焙契约：

| 输出 | 内容 | 规则 |
|---|---|---|
| `name_color.png` | 不含强方向光的颜色与透明度 | sRGB；可有很轻的手绘明暗，不固定一盏主光的影子 |
| `name_normal.png` | 适配 sprite 平面的切线基法线 | 数据纹理；平面法线接近 (0.5, 0.5, 1)，不做显示色调映射 |
| `name_ao.png` | 局部遮蔽 | 数据纹理；保留独立文件与可控强度 |
| `name_emission.png`（可选） | 指示灯/发光面 | 与灯光影响分开，避免整台机器发光 |
| `name_mask.png`（可选） | 各灯光 Blend Style 使用的通道 | 含义写入素材元数据；不是默认 PBR AO 插槽 |

所有输出使用同一个正交相机、尺寸、裁切窗口、pivot 和透明轮廓；不得每张单独自动裁边。机械正面保持横剖面可读，可略露顶部/侧面但不要让所有建筑的透视消失点各不相同。每格像素密度采用同一规范，尺寸变化通过 footprint 而非随意缩图实现。

Blender 的普通世界空间/相机空间 Normal pass 不能直接当作 Unity sprite 的切线法线。可把表面法线投影到固定 sprite 平面的切线基，再编码到 0–1；也可向与输出视图对齐的平面烘焙。具体轴向取决于相机朝向，必须用球面或倒角测试件在 Unity 中左右、上下移动灯光检查，不凭“图是蓝紫色”判定正确。

### 已在本机 URP 包中核查的接入要求

Unity 的 Secondary Textures 文档说明 sprite 可以绑定法线与遮罩纹理。[S12](https://docs.unity3d.com/Packages/com.unity.render-pipelines.universal@14.0/manual/SecondaryTextures.html) 本机 `Library/PackageCache/com.unity.render-pipelines.universal@14.0.12` 的 `Sprite-Lit-Default.shader` 和 `Renderer2DDataAuthoring.cs` 使用准确属性名 **`_NormalMap`、`_MaskTex`**。文档显示名与代码字段不要混用。

材质使用 Sprite Lit；2D Light 的 Normal Map Quality 不能保持 Disabled。普通 Sprite-Lit-Default 不会因为文件叫 AO 就自动应用 AO：首版可轻度合入 color，同时保留原始 color/AO；要独立可调则做专用 Sprite Lit ShaderGraph。不能把普通 2D mask 理解成 URP 3D Lit 的金属度/粗糙度/AO 一套通道。

贴图验收：透明边无黑边；color/normal/AO 在同一像素对齐；向右移动灯时凸面右侧响应一致；翻转 sprite 后法线正确；各邻接变体接缝不漏底色；远景降饱和且不遮住端口与告警。AO 不等于动态投影，动态遮挡需独立 ShadowCaster2D 或后续方案。

## 11. 分阶段验收，避免“有画面等于已完成”

| 阶段 | 交付标准 | 尚不能因此声称完成 |
|---|---|---|
| A 编辑器切片 | 一键生成、真实落盘、独立前景、区域可查、连接可重建 | 完整气体/人员模拟 |
| B 可运行网络 | 压差输送、组分守恒、阀门和双出口设备、堵塞可定位 | 全热力学、燃烧、相变完整性 |
| C 人员闭环 | 可达任务、材料预约、实际施工/维修、区域进入条件 | 完整殖民者生活与社会系统 |
| D 热与反应 | 冷凝守恒、热汇、有限冷却、条件反应、存读档一致 | 真实工业仿真或任意元素反应 |

优先验证对称支路、满罐、关阀、拆管、合并房间、重新加载和快速暂停，防止物料复制、施工顺序优势与负库存。美术验收独立检查法线方向和连接接缝；不能以逻辑测试通过代替画面验证。

后续最值得观察的玩家行为：是否主动保留天然盖层；能否沿告警找到真正堵住的出口；能否提出第二种恢复方式；是否因为环境处理成功而愿意继续挖掘。若这些还不成立，应继续打磨观测与布局，而不是先堆更多气体种类。

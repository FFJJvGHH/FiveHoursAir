# 生存开局与人员循环

## 本轮方向

新工程从三名人员、一个打印舱和原料开始。天然洞穴中的氧气是有限库存；设备需要施工，更多人员同时意味着更多工作能力和更高氧气需求。打印候选人需要玩家主动接纳，也可以选择补给或拒绝。窒息和危险冲击会伤害人员，死亡永久保留，未完成工作可由其他人员接手。

标题只保留游戏名。操作说明由玩家主动打开；主界面展示实际人口、氧气供需和故障，删除标题下方的教学式小字与默认流程宣传。

## GitHub skill 搜索与采用

按本轮要求先搜索 GitHub，再实施。未安装或执行第三方仓库脚本。

- [Unity 官方 UI skill](https://github.com/Unity-Technologies/skills/blob/main/skills/ui/SKILL.md)：先识别现有 UI 系统。项目使用 OnGUI，本轮沿用既有实现，避免为布局调整迁移整套 UI。
- [Unity 官方 IMGUI skill](https://github.com/Unity-Technologies/skills/blob/main/skills/ui-imgui/SKILL.md)：参考既有脚本修改、成对布局、禁用不可用操作等规范。其对新项目 UI 框架的建议不用于本轮整体重写。
- [Game Design Fundamentals](https://github.com/fcsouza/agent-skills/blob/main/plugins/game-dev/design/game-design-fundamentals/SKILL.md)：采用资源来源与消耗闭环、节制引导、保留玩家选择的原则，落实为可选扩员、真实耗氧和逐步建设。

《缺氧》作为开局结构与人员循环的参考。本项目仍使用自己的简化时间、气体单位和参数，不声称复刻完整食物、睡眠、疾病或生活设施系统。

## 验证入口

Unity 菜单：深压 → 验证 → 生存开局验收。结果保存在工程上级 `outputs/v07-validation.txt`。验证包括既有模拟回归、人员生命周期、真实开局施工与存档恢复。实际执行结果以该报告为准。

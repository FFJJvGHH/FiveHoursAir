# 深压 v0.6：工程系统与表现改造

本轮依据用户的实际问题修改 Unity 工程：悬空素材、电力与电线、气体设备分工、资源控制、取样和揭雾、气体扩散/危险/工业用途、图标科技树、人物待机细节。所有危险阈值与消耗数值都是游戏平衡参数，不是现实工程规范。

## 实际玩法

玩家管理有限的燃料、建材、工作时间和气体。发电机消耗燃料，已经施工的电线决定哪些设备能工作。采集泵从所在空腔抽气，管网将气体送入缓冲、调压、分离和供气设备；人物实际消耗局部氧气并产生 CO₂。供气和清除污染能改变工作区环境，断线或停产后缓冲会逐步耗尽。

页岩产出燃料与矿料，拆挖金属地块可回收合金。制造支持单批/多批和目标库存：不足时安排生产，到达目标停止，仓满停止继续投料。工单预留与可用库存分别显示。

已存在的站内电线作为旧站基础设施保留；新建设备必须接入电线。新关卡生成入口也会配置新版电网、应急储气与人物表现，避免生成旧式无电线基地。

## 电力与气体设施

| 设施 | 作用与约束 |
|---|---|
| 发电机 | 有限燃料换取功率；只供给接入同一电网的负载 |
| 电线 | 消耗合金与人员工时，完工后才导电；断线重算回路 |
| 电池 | 存储实际能量，按供需充放电，受容量与传输功率限制 |
| 采集泵 | 耗电抽取附近真实气体，节点满载后等待出口 |
| 原气罐 | 接受混合气，缓冲源头和处理设备的供需变化 |
| 调压器 | 限制接收压力，控制下游管路条件 |
| 分离器 | 产品氧气与尾气分别输出；两边都需要去处 |
| 氧气罐 | 接受符合本游戏品质规则的清洁富氧产品，拒绝可燃/工业蒸气污染 |
| 尾气罐 | 接收低氧尾气，作为分离副产物的暂存空间 |
| 供气口 | 把节点库存送回所在格，根据局部目标氧分压和总压停止 |
| 排气口 | 把库存排到所在区域，需放在合适隔离区；不会删除气体 |
| CO₂ 回收机 | 从所在格选择性抽取 CO₂，仍需接管处理库存 |
| 工业蒸气回收机 | 累计回收 5 mol 工业蒸气制成一份密封试剂；仓满停止，试剂可用于高效电子元件配方 |

燃料从基地库存扣除，建造和制造已有人员取料过程；尚未实现逐台设备的独立燃料搬运仓或多电压变压器系统。

## 逐格气氛与事故

空腔按格保存 O₂、N₂、CO₂、水蒸气、甲烷和架空工业蒸气，以及温度。相邻格采用有限、守恒的扩散；岩壁阻挡传播。房间数据是逐格库存汇总，不再是另一份独立库存。

- 凿穿明显压差隔层前显示风险提示。实际开挖会触发有方向的喷流和扩散冲击，影响近处人员站位与应急气量。
- 普通气体相遇只混合。燃爆需要可燃组分、氧气和通电热作设备满足游戏条件；反应消耗物料，产生热、CO₂ 和水蒸气。
- 工业蒸气会随通路扩散，并影响人员气氛缓冲和工作效率；回收后可加工成工业材料，因此隔离、抽取和利用存在取舍。
- 人员拥有有限的气氛缓冲；不适环境会消耗缓冲并降低效率。本版本没有完整伤病、死亡、饥饿和睡眠模拟，也没有岩体坍塌或建筑碎裂系统。

气体 shader 读取真实局部组分、压力与温度，表现空间梯度和漂移纹理。颜色只是反馈；实际库存与扩散由模拟控制。工业蒸气使用紫色，可燃组分使用暖黄色，未知区域与岩石保持遮挡。

## 勘探与迷雾

取样是人员工单：找到可达探测站位、移动、作业、记录样本。每个洞层首次真实取样获得研究数据，取消和重复下单不会重复发奖。

人员视野与已经使用/发现的设施自动揭开附近区域，探索记忆保留。实墙和斜角遮挡视线，未发现的废弃设备不会远程公开整片地图。开挖通路后视野继续展开；危险区域的取样不等于安全进入许可。

扫描效果包含探针连线、洞层轮廓和扩散环。原先免费“隔绝装备”远程揭图开关已移除。

## 素材、人物与界面

机器使用可见 alpha 底脚对齐地面，挂灯和风口使用独立安装点。床铺、花槽、旧控制台及箱子也按真实地板定位，并有整体选择根对象。颜色、法线、AO 的 UV 关系保留。

人物增加同一 Blender 模型制作的待机细节、搬运与攀爬帧；脚底锚点保持稳定，步态与实际位移一致，暂停冻结动作。机器底座固定，转子和指示灯跟随真实供电、工作和气流；电池显示实际电量。

科技树使用独立的小图标、分支与依赖路径，旁边显示稳定的详情区。搜索可匹配科技和解锁的设备/工艺。工程提示改为可折叠的运行状态与世界内故障图标；主菜单以气源—采集—处理—缓冲—供气示意表达主题。

## Skill 使用记录

本轮读取并采用下列 skill 的方法，没有把网页运行库装进 Unity，也不声称第三方技能可以自动保证视觉质量。

- [interface-design](https://github.com/Dammyjay93/interface-design/blob/main/.claude/skills/interface-design/SKILL.md)：层级、信息密度、稳定详情区、统一状态和间距。
- [Emil Kowalski animate](https://github.com/emilkowalski/skills/blob/main/skills/animate/SKILL.md)：反馈应对应状态、可中断，不给高频操作增加等待。
- [create-game-assets](https://github.com/gamedev-skills/awesome-gamedev-agent-skills/blob/main/skills/disciplines/create-game-assets/SKILL.md) 及 raster-pipeline：可见边界、统一比例和锚点、配套法线/AO、游戏内验收。
- [game-ui-ux](https://github.com/gamedev-skills/awesome-gamedev-agent-skills/blob/main/skills/disciplines/game-ui-ux/SKILL.md)：按窗口缩放、菜单输入层级、世界反馈与界面信息区分。其 Unity 6 示例未直接照搬到 2022.3。

验证日志、实际游戏截图和可执行版本保存在工程上级 `outputs`。最终以本轮最新的 `v06-validation.txt`、`v06-active-save.txt`、`v06-live-simulation.txt`、`v06-build.txt` 为准。

# 设备生产与界面 v0.9

本轮直接纠正交互结构：建造是主工具栏旁的一个独立格子，删除 v0.8 加在上方的整排常用设施。物品生产必须从实体生产设备发起。C 和底部“生产”只打开设备列表；没有合成台时只能前往建造，不能在全局列表直接制造。

## 终末地调研与采用范围

核对了[官方 Beta Test II 研发通讯](https://endfield.gryphline.com/en-us/news/1340)及其中的[实际配方详情演示图](https://web-static.hg-cdn.com/upload/image/20251031/d2ee9ad0a5266aab358b09f92d237d4f.jpg)：设备身份、开关、原料和产物、当前配方及电力异常在同一设备界面内可见。原图左侧是物品仓储，右侧呈现设备的投入和产出；错误反馈紧贴相应生产设备。另核对[官方版本说明](https://endfield.hypergryph.com/news/9343)中装备制造入口跳转、批量制作和简易配方定位的优化。

终末地也存在独立的简易制作、装备加工等界面，不能据此说它所有合成都必须先选择实体设备。本项目按用户要求选择“实体设备制造”规则，采用其明确的设备归属、输入/产出分区、配方定位、批量操作及就地反馈。没有把传送带、背包拖放或整套装备养成凭空加入本项目。

## 本次实现

1. 点击已建成合成台的“打开本台生产”，或从生产设备目录选择一台。
2. 左侧仅列本台支持的配方；右侧并列投入原料与产出物品，显示库存、所需数量和基础工时。
3. 选择批次，加入本台队列；工人实际到仓库取料、走到指定设备、完成加工后才产生物品。
4. 工单从建立开始绑定机器，不在移动时改选另一台。队列按本台先后顺序执行；关闭/断电会保留队列并阻塞，不能靠完成重试绕过停机。机器移除则取消并退款一次。
5. 持续补货也是某台设备的目标，存档保存机器身份；同配方可以分别由不同设备管理。

对应文件：`DeepStationProductionUI.cs`、`DeepGameSession.Requests.cs`、`DeepGameSession.Execution.cs`、`DeepGameSession.Production.cs` 和存档实现。设备目录没有 `RequestCraft` 提交入口。

## 动效不是只改一个按钮

阅读并应用 [LottieFiles motion-design SKILL](https://github.com/LottieFiles/motion-design-skill/blob/main/skills/motion-design/SKILL.md)及其 [Timing/Easing](https://github.com/LottieFiles/motion-design-skill/blob/main/skills/motion-design/reference/timing-easing-tables.md)、[State Feedback](https://github.com/LottieFiles/motion-design-skill/blob/main/skills/motion-design/patterns/state-feedback.md)。这些文件作为设计指南使用，没有安装或执行第三方脚本。

| 交互 | 具体反馈 |
| --- | --- |
| 建造独立格、普通按钮、设备卡片 | 约90ms悬停、180ms按下回弹；视觉变化不改变点击范围 |
| 分类、配方、人员偏好、工单优先级、取消 | 统一的局部高亮与底边确认 |
| 面板打开/关闭 | 220ms缓出进入，160ms加速退出；文字、图标、背景共同淡出；退出阶段不能误触 |
| 面板间切换 | 工具栏的新选择在同一GUI事件中立即接管，旧面板不会把点击覆盖回去 |
| 配方切换 | 标题短距离缓出，与选中配方高亮同步 |
| 本台生产 | 真实进度缓动、队列身份、阻塞原因、最近完成反馈 |
| 不可提交/失败 | 禁用提交、就地原因；失败反馈用暖色和独立音调，不再被先前的点击音吞掉 |
| 世界机器开关与仓储 | 真实事件触发短暂状态变化；见世界美术文档 |

## 旧场景与验证

本轮发现用户正在使用 `DeepPressureColony 15`，因此增加 `DeepWorldArtUpgrade` 的Play兼容入口。旧场景和后续新人物/建筑会获得相同的调色、灯光、仓库修正与必要设备反馈，无需重新生成地图。它不保存场景、不重置地图、不克隆材质；每个对象处理一次，保留用户自定义灯和之后的手动调整。

因为原Unity工程正在使用，本轮在 `outputs/v09-check/Project` 临时副本执行Unity测试及真实GameView渲染，不关闭原Unity实例。最终报告为 `outputs/v09-validation.txt`；真实UI渲染为 `v09-home.png`、`v09-production.png`、`v09-stopped.png`、`v09-device-list.png`、`v09-build.png`。这些来自本项目实际OnGUI和世界渲染，不是另写的界面示意图。

本轮已实际执行设备生产3组、NPC15组、持久化11组，以及既有气体、电网、人员、危险反应、场景开局和视觉兼容验收。GameView验证会通过C键进入设备目录，向独立建造格发送实际鼠标事件，并校验打开的面板；其余截图覆盖加工和关机后的真实队列状态。最新执行结果以报告中的PASS/FAIL为准。预览自动存档组件已断开会话引用，不写入玩家存档。
